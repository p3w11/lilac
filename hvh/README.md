# FLUX HvH — портал сервера

Сайт для HvH-сервера на CS:GO (FLUX HvH — ONLY SCOUT, MIRAGE, Roll Fix): витрина, магазин услуг,
пополнение баланса, личный кабинет и встроенная админ-панель.
Всё работает локально, без внешних зависимостей и без интернета.

```
node server.js
```

* сайт — http://127.0.0.1:8813/
* админка — http://127.0.0.1:8813/admin
* логин `admin`, пароль `admin` (смени в панели)

Порт и папку можно поменять переменными окружения:

```
PORT=8080 HOST=0.0.0.0 ADMIN_PASSWORD=секрет node server.js
```

## Что умеет

### Сайт
* **Двуязычность RU/EN** — переключатель в шапке, выбор запоминается.
  Весь контент (тексты, виджеты, новости, услуги) хранится в базе в двух
  языках, а интерфейс — в словарях `assets/site.js`.
* **Кнопка «Админка»** в шапке показывается только тем, у кого есть права
  администратора; остальные её не видят (но `/admin` по прямой ссылке
  всё равно проверяет права на сервере).
* **Правки из админки видны на сайте без перезагрузки** — содержимое
  опрашивается каждые 10 секунд, и как только что-то изменилось, страница
  сама перерисовывается и показывает плашку «Контент обновлён».
* **Виджеты** — админ добавляет блоки в любую позицию страницы:
  * `text` — произвольный текст;
  * `banner` — акцентный баннер (шапка);
  * `servers` — заготовка под список серверов;
  * `monitor` — виджет мониторинга monwave.ru (ID из ссылки
    `https://monwave.ru/api/widget/17984`); сервер отдаёт его без логотипа
    и в палитре сайта.
  Порядок меняется кнопками ↑/↓, виджет можно скрыть (исчезнет с сайта) или
  удалить — с подтверждением и плашкой. Скрытый виджет всегда можно вернуть
  кнопкой «показать».
* **Живой мониторинг серверов** — настоящий UDP-опрос Source Engine Query
  (A2S_INFO): онлайн/оффлайн, игроки, карта, пинг. Обновление раз в минуту
  на клиенте и в фоне каждые 45 секунд.
* **Магазин услуг** — карточки с ценой, списком возможностей и сроком.
  Покупка списывается с внутреннего баланса.
* **Пополнение баланса** — карта / СБП / USDT. Реквизиты берутся из настроек
  и показываются прямо в форме (можно скопировать одним кликом).
  Игрок переводит на реальную карту/номер и жмёт «Я оплатил» — заявка уходит
  админу, он нажимает «зачислить», и рубли падают на баланс.
  Для демонстрации есть кнопка мгновенной оплаты.
* **Личный кабинет** — баланс, история пополнений, заказы, смена пароля.
* **Регистрация по почте** — логин, e-mail и пароль; почта уникальна и
  показывается в админке.

| Раздел | Что делает |

| Виджеты | добавление, редактирование, скрытие, порядок, удаление |
| Услуги | цены, описания, сроки, бейджи, порядок |
| Серверы | добавление серверов, тег игры, лимит слотов, живой статус |
| Новости | публикация с переводом на два языка |
| Пользователи | **выдать/снять админку**, **выдать игровую админку**, **начислить или списать рубли**, сброс пароля, **привязка игрового аккаунта**, **выгрузка базы пользователей в CSV**. Регистрация — по почте, логину и паролю |
| Донаты | подтверждение (рубли начислятся) или отклонение заявок |
| Заказы | отметить услугу как выданную (вручную), SteamID игрока — копируется в один клик |
| Лог действий | кто что сделал |

  data/portal.db   база (создаётся сама)
  public/
    index.html     витрина
    admin.html     админка
    assets/style.css  тема (фиолетовый неон)
    assets/site.js     логика сайта, i18n
    assets/admin.js    логика админки
    assets/admin.css   стили админки

### База
Встроенный `node:sqlite` (Node 22+), внешних пакетов нет вообще.
Таблицы: `users`, `sessions`, `settings`, `widgets`, `services`, `servers`,
`server_stats`, `donations`, `orders`, `news`, `audit`.

### Безопасность (демо-уровень, но без дыр)
* пароли — `scrypt` со случайной солью, сравнение через `timingSafeEqual`;
* e-mail проверяется на формат и уникальность при регистрации;
* сессия — httpOnly-cookie `SameSite=Lax`, срок 14 дней;
* CSRF-токен в сессии, требуется заголовок `x-csrf` на всех изменениях;
* все SQL-запросы параметризованные;
* антибрутфорс: 8 попыток входа с одного IP за 10 минут;
* экранирование пользовательского текста в DOM.

Перед публикацией в интернете: смени пароль админа, поставь HTTPS
(nginx/Caddy с проксированием на 127.0.0.1:8813) и подключи реальный
платёжный провайдер вместо демо-оплаты.

### Мониторинг серверов
`monitor.js` шлёт UDP-пакет `\xFF\xFF\xFF\xFFTSource Engine Query` и разбирает
ответ: имя, карта, игроки, максимум, пинг и теги сервера. Это тот же
протокол, которым работает панель SourceMod, поэтому подойдёт любой сервер
на Source/SourceMod.

Поддержаны оба формата ответа: ключевой (Source 2016+, `hostname\0map\0…`)
и классический позиционный. В классическом после строки `game` идут
appid, версия, **число игроков**, **максимум игроков**, служебные байты,
строка версии и «расширенная» строка с тегами.

Проверено на живых серверах:

| сервер | результат |
|---|---|
| `185.9.145.160:29999` (FLUX HvH) | 11/32, de_mirage, 59 мс, теги `tick,comp,hvh,mirage,scout,insecure` |
| `185.9.145.159:28888` | 8/64, de_mirage |
| `46.174.55.118:1337` | 4/32, g_de_mirage |

### Привязка пользователей

У каждого пользователя есть три идентификатора:

| поле | для чего |
|---|---|
| `login` | логин на сайте (вход в кабинет) |
| `email` | почта (единственная, проверяется) |
| `game_login` | ник в CS:GO — по нему ты ищешь игрока в админке сервера |
| `steam_id` | SteamID игрока (необязательно) |

**Привязать вручную** — кнопка «привязать» в разделе «Пользователи»: вводишь
ник и SteamID, они пишутся в базу и видны в колонке «Игровой аккаунт».

**Добавить пачкой** — раздел «Пользователи» → «Массовое добавление и привязка»:
вставляешь CSV, существующие логины обновляются, новые создаются.

```
логин;почта;игровой_ник;steam_id;баланс;игровая_админка;админка
flx_player;player@mail.ru;flx_player;STEAM_0:1:12345;1500;1;0
flx_admin;boss@mail.ru;flx_admin;STEAM_0:1:999;0;1;1
```

Разделитель — «;» или «,». Флаги понимают `1/0`, `да/нет`, `true/false`.
Пустое поле ничего не затирает. Кнопка «↓ Выгрузить CSV» отдаёт текущую базу
в CSV — можно поправить в Excel и загрузить обратно.

**Выгрузка базы.** Раздел «Пользователи» → «База данных пользователей»:
кнопка «Выгрузить базу (CSV)» отдаёт всю базу в том же формате, что и импорт,
— можно править в Excel и загружать обратно. Там же «Копировать» и «↓ Файл».

**Как связать с базой самого сервера.** На SourceMod-сервере админы лежат в
`addons/sourcemod/data/admins.json` (или в `admin.sqlite`/`users.cfg`, если
используется Admin Manager). Схема одна и та же — id, name, flags, steamid:

```powershell
# выгрузить админов сервера в CSV для импорта
node -e "const a=require('C:/server/addons/sourcemod/data/admins.json');
console.log(a.map(x=>[x.name,x.name+'@mail.ru',x.steamid||''].join(';')).join('
'))"
```

Дальше вставляешь результат в поле импорта. Синхронизация двусторонняя:
выдал права на сайте — выставил флаг в JSON; забрал в JSON — забрал на сайте.
Если хочешь полной автоматики, скажи — добавлю разбор `admins.json` напрямую
из папки сервера (путь задаётся в настройках).

### Внешняя база пользователей (MySQL) — привязка к старому сайту

Портал умеет брать пользователей не из своей базы, а из **внешней MySQL** —
той самой, что на старом сайте (таблица `flux_users`, раньше `flute_users`).
Тогда логин, почта, пароль и баланс — общие со старым сайтом и игровым сервером.

Админка → «Пользователи» → **«Источник базы пользователей»**:

| Режим | Когда использовать |
|---|---|
| Встроенная база портала (SQLite) | по умолчанию, всё в одном месте |
| Внешняя MySQL — напрямую | если порт 3306 доступен с этой машины (VDS, локальный MySQL) |
| Внешняя MySQL — через PHP-мост | на шаред-хостинге, где MySQL закрыт снаружи |

**Что берётся из внешней таблицы**

| Поле таблицы | для чего в портале |
|---|---|
| `login` | логин (вход и по логину, и по почте) |
| `email` | почта |
| `password` | пароль — **bcrypt** (`$2y$`/`$2a$`/`$2b$`), как у PHP |
| `balance` | баланс в рублях (общий со старым сайтом) |
| `name` | отображаемое имя / игровой ник |
| `last_logged`, `created_at`, `updated_at` | время входа и регистрации |
| `verified`, `approved`, `hidden`, `is_temporary`, `deleted_at` | служебные флаги |

Остальные поля (`steam_id`, игровой ник, права админа, заметки) хранятся в базе
портала — это «зеркало». Если добавить в таблицу колонки `steam_id`, `game_login`,
`game_admin`, `is_admin` (см. `bridge/flux_users.sql`), портал начнёт писать
и их напрямую в таблицу.

Колонки определяются автоматически: админка показывает, что нашлось
(«Показать структуру»), и ругается, если не хватает `login` / `email` / `password`.

**Новый пользователь с сайта** попадает прямо во внешнюю таблицу:
пароль хешируется bcrypt-ом, поэтому старый сайт и форум его тоже увидят.

**Если MySQL закрыт снаружи** (обычная история на шаред-хостинге) — залей на
хостинг файл `bridge/flux_users.php`, впиши в него доступы к базе и секретный
ключ, потом в админке выбери режим «через PHP-мост» и укажи адрес файла.

```php
const FLUX_DB_HOST  = 'sql123.ds-host.su';
const FLUX_DB_NAME  = 'if0_12345678_flux';
const FLUX_DB_USER  = 'if0_12345678';
const FLUX_DB_PASS  = 'пароль';
const FLUX_DB_TABLE = 'flux_users';
const FLUX_TOKEN    = 'длинная_случайная_строка';
```

Мост принимает только `SELECT/SHOW` (чтение) и `INSERT/UPDATE/DELETE`
(изменение) — и только с правильным `X-Flux-Token`.

**Создать таблицу** — `bridge/flux_users.sql` (структура как у старой
`flute_users` + рекомендуемые дополнения).

### Игровая статистика (MySQL, только чтение)

Модуль `gamestats.js` читает те же MySQL-креды, что и `users.js`
(настройки внешней базы), и кэширует ответ на 60 секунд.

| Карточка / блок | Таблица | Запрос |
|---|---|---|
| Всего игроков | `lvl_base` | `COUNT(*)` |
| Игроков за 7 дн. | `lvl_base` | `lastconnect >= NOW() - 7 дней` |
| Игроков сегодня | `lvl_base` | `lastconnect >= CURDATE()` |
| VIP игроков | `vip_users` | `expires = 0 OR expires > NOW()` |
| Всего забанено | `sb_bans` | активные баны |
| Всего заглушено | `sb_comms` | активные муты/гаги |
| Последний дроп | `neo_cards_history` + `neo_cards_rewards` | последние 12, имена из `lvl_base` |

Дополнительно есть read-only API для будущих страниц:

- `GET /api/game/bans?limit=100` — список банов (`sb_bans`)
- `GET /api/game/mutes?limit=100` — список мутов/гагов (`sb_comms`)

Если MySQL недоступна, `/api/stats` отдаёт последние удачные значения
(или нули), сайт при этом продолжает работать.

### Вход через Steam (OpenID 2.0)

**Вход и регистрация на сайте — только через Steam.** Модалка входа
(`#popupAuth`) содержит одну кнопку «Войти через Steam»; формы логина и
пароля нет. `POST /api/auth/register` отключён, а `POST /api/auth/login`
принимает только администраторов (нужен для входа в `/admin`).

Кнопка «Войти через Steam» ведёт на `/auth/steam`:

1. `/auth/steam` — редирект на `steamcommunity.com/openid/login`
   (`return_to` = `<база>/auth/steam/callback`);
2. Steam возвращает на `/auth/steam/callback`, портал проверяет подпись
   (`check_authentication`) и достаёт SteamID64;
3. ищет пользователя по `steam_id` (`users.js → findBySteam`, включая внешнюю
   MySQL), если нет — создаёт аккаунт: логин из ника Steam, почта
   `<steamid>@steam.local`, случайный пароль;
4. сохраняет ник и аватар Steam, пишет запись в `flux_steam`, открывает
   сессию и возвращает на `/?steam=ok`.

Если пользователь уже вошёл — Steam не логинит заново, а **привязывает**
SteamID к текущему аккаунту (`/?steam=linked`). Занятый SteamID —
`/?steam=taken`.

**Таблица `flux_steam`.** Создаётся автоматически при старте (и локально в
SQLite, и во внешней MySQL рядом с `flux_users`). Хранит все Steam-аккаунты,
которые заходили на портал:

| Поле | Что это |
|---|---|
| `steam_id` | SteamID64 (первичный ключ) |
| `steam64` | дубль SteamID64 |
| `persona` | ник в Steam |
| `avatar` | ссылка на аватар (`_full.jpg`) |
| `background` | фон профиля Steam |
| `login` | логин портала, к которому привязан Steam |
| `user_id` | id локального пользователя портала |
| `first_seen` / `last_login` | первый и последний вход |
| `last_ip` | IP последнего входа |

Аватар также сохраняется в `users.avatar` и в `flux_users.avatar` — из него
берётся картинка в шапке и в меню пользователя (вместо первой буквы ника).

**Адрес портала.** Для локальной проверки берётся из заголовка `Host`
(`http://127.0.0.1:8813`). На проде задай один из вариантов:

- настройка `auth.base_url` (таблица `settings`): `https://flux-hvh.space`
- переменная окружения `PUBLIC_URL=https://flux-hvh.space`

Иначе Steam вернёт на тот адрес, по которому открыт сайт.

Профиль (ник, аватар, фон) тянется из публичных страниц Steam — API-ключ
не нужен, кэш 10 минут.

### Страница профиля

`/profile` — свой профиль (нужен вход, иначе редирект на `/?auth=login`),
`/profiles/<SteamID64>/` — публичный профиль любого игрока. Вёрстка и стили
взяты со старой страницы `flux-hvh.space/profiles/...` как есть — модуль
`public/app/modules/module_page_profiles/assets/css/1.css`, классы
`.profile_user_card`, `.user_sec_block`, `.general_info` и т.д.
Слева — карточка игрока (фон и аватар Steam, картинка звания
`/storage/cache/img/ranks/default/<rank>.svg`, статус, роли, иконки-разделы),
справа — блок «Информация об игроке» с колонками.

Данные берутся из `lvl_base` по `steam = STEAM_1:Y:Z`:

| На сайте | Поле |
|---|---|
| Звание / Опыт | `rank` / `value` |
| Место | позиция по `value` (COUNT + 1) |
| Наиграно | `playtime` (секунды → часы) |
| Победы | `round_win / (round_win + round_lose)` |
| Рангов | `round_win + round_lose` |
| Убийств / Смертей / К/Д | `kills` / `deaths` / расчёт |
| Ассистов / В голову / Встречи / Попаданий | `assists` / `headshots` / `shoots` / `hits` |
| SteamID32 / SteamID64 | `steam` / из него |

API: `GET /api/game/profile?id=<SteamID64 | STEAM_1:Y:Z | [U:1:...]>` —
возвращает `{ profile, portal, steam }`. В `steam` лежат `avatar` и `background`,
которые сервер достаёт из публичного профиля Steam (`?xml=1` и HTML страницы,
кэш 10 минут, API-ключ не нужен); если у игрока нет фона — карточка показывает
градиент. Админ-иконка в карточке — только админам.

### Интерфейс: копия шаблона flux-hvh.space

Публичная часть — это точная копия шаблона `neo_remastered` со старого сайта:

- разметка, CSS, спрайт иконок, шрифты и картинки карт лежат локально:
  `public/app/templates/neo_remastered/…`, `public/app/modules/…`,
  `public/resources/img/sprite.svg`, `public/storage/…`;
- наши дополнения (меню пользователя, модалка входа через Steam,
  уведомления, страница профиля) — в `public/assets/site.css`;
- вся динамика — в `public/assets/site.js` (без jQuery).

Что подключено к нашему API:

| Блок | Источник |
|---|---|
| счётчик онлайна (шапка + попап) | `/api/stats` |
| 6 карточек статистики | `/api/stats` (total/d7/today/vip/banned/muted) |
| блок серверов + обновление | `/api/servers`, `/api/servers/refresh` |
| топ донатеров (7 / 30 / всё время) | `/api/stats` → `tops_by_day` |
| «последний дроп из карточек» | последние оплаченные донаты |
| баннеры | виджеты (`/api/site`) |
| вход / регистрация | только Steam: `/auth/steam` (OpenID 2.0) |
| уведомления в шапке | `#openNotifications` + `localStorage` |
| пополнение | `/api/donate` (создаёт заявку) |

Заглушки до подключения игровых баз: `vip`, `banned`, `muted` = 0.
В той же MySQL (`gs143084`) уже есть таблицы `sb_bans`, `sb_banlog`,
`flute_server_statuses` — их можно использовать для этих цифр.

В шапке, сразу после кнопки языка, стоит колокольчик уведомлений: счётчик
непрочитанных, выпадающий список и кнопка «Очистить». Прочитанные и
очищенные уведомления запоминаются в `localStorage`.

Подвал: «Лучшие сервера для читеров.» и «Сделано с ♥ Flux HvH» (без
onevalve). Он виден и на главной, и на странице профиля.

### Роли (user / admin)

Роли лежат в той же базе, что и пользователи — в таблицах `flux_roles`
и `flux_user_roles` (создаются скриптом `bridge/flux_roles.sql`).

| Таблица | что в ней |
|---|---|
| `flux_roles` | сами роли: `id`, `name`, `title`, `permissions`, `is_admin` |
| `flux_user_roles` | кто какую роль имеет: `user_id`, `role_id` |

Базовые роли засеяны: **user** (обычный) и **admin** (администратор,
`is_admin = 1`). Права портал берёт из роли — колонка `is_admin` в
`flux_users` тоже синхронизируется.

Как это работает:
- при регистрации на сайте новому пользователю выдаётся роль `user`;
- в админке → «Пользователи» → колонка **«Роль»** → «изменить» — можно
  выдать/снять роль (пишется в `flux_user_roles`);
- кнопка «Админка» на сайте показывается только при роли `admin`;
- локальные аккаунты портала (в т.ч. запасной `admin`) можно перенести в
  `flux_users` кнопкой **«в flux_users»** — портал спросит пароль и создаст
  запись с bcrypt-хешем и нужной ролью.

|---|---|
| Хост | `185.9.145.160:3306` (MariaDB 10.11) |
| База данных | `gs143084` |
| Пользователь | `gs143084` |
| Таблица | `flux_users` |
| Режим | Внешняя MySQL — напрямую |

Пароль хранится в базе портала (открытым текстом) — как и пароль RCON.

**Что портал делает в этой базе:** только `flux_users`, и только эти операции —
`SELECT` (список/поиск пользователя), `INSERT` (регистрация на сайте),
`UPDATE` (пароль, баланс, SteamID, игровой ник, права). Остальные таблицы
(`flute_*`, `vip_users`, `shop_*`, `sb_*` и прочие) портал не читает и не
трогает никогда.

Если внешняя база недоступна — портал не падает: админ заходит по локальной
учётке, остальные функции временно недоступны.

Если всё же хочешь управлять сервером из портала, включи на сервере:

```

```

и перезапусти сервер.

Ниже — справка по тому, как это работало.

**Как включить на сервере** — в `addons/sourcemod/configs/server.cfg`:

```
rcon_password "свой_длинный_пароль"
```

Порт RCON по умолчанию — тот же, что и у игры (`27015`).

**Что умеет панель**

| блок | что делает |
|---|---|
| RCON-доступ | хост, порт, пароль + кнопка проверки связи |
| Игроки онлайн | список с ником, счётом и временем в игре (A2S_PLAYER) |

| Консоль сервера | любая команда: `kick`, `ban_add`, `sm_kick`, `say`, `status`… |
| Быстрые действия | смена карты, объявление в чат, перезапуск сервера |

Пароль RCON хранится в базе портала в открытом виде — не выкладывай
`data/portal.db` наружу.

## Как привязать сайт к серверу

Чтобы покупка на сайте выдавала права в игре, нужна связка «портал -> сервер».
В SourceMod админка живёт в файле `addons/sourcemod/data/admins.json`,
а самого SourceMod нельзя заставить выдать права командой (команды
`sm_addadmin` не существует) — поэтому связка делается одним из двух способов.

### Шаг 1. Включи RCON на сервере

`addons/sourcemod/configs/server.cfg`:

```
rcon_password "свой_длинный_пароль"
```

Порт RCON по умолчанию тот же, что у игры (27015).

### Шаг 2. Укажи доступ в портале

Админка -> «Управление сервером» -> блок «RCON-доступ»: хост, порт, пароль,
кнопка «Сохранить и проверить». Бейдж покажет «подключено» или «не отвечает».

### Шаг 3. Выбери способ выдачи

**Способ A. Файловый — работает на 1.10/1.11/1.12, ничего доустанавливать не надо.**

В том же разделе укажи путь к файлу на сервере:

```
/home/csgo/addons/sourcemod/data/admins.json
```

Портал сам допишет запись нужного вида:

```json
{ "steamid": "STEAM_0:1:12345678", "name": "flx_player", "flags": "b", "immunity": 0, "is_restricted": false }
```

Права подхватятся при смене карты (или командой `sm_reloadadmins`, если она
есть в твоей версии). Путь должен быть доступен процессу портала —
то есть портал и сервер на одном VPS или в одной сети с общей папкой.

**Способ B. Мост — если портал на другом хосте. Нужен SourceMod 1.12+.**

Скачай мост в админке («Управление сервером» -> блок «Мост выдачи прав»)
и положи `flx_bridge.smx` в:

```
addons/sourcemod/plugins/flx_bridge.smx
```

Мост принимает по RCON:

```
flx_grant  <steamid> [ник] [флаги]
flx_revoke <steamid>
```

и выдаёт права прямо на сервере. Исходник тоже приложен (`flx_bridge.sp`).

### Шаг 4. Настрой услугу

В админке -> «Услуги» -> у нужной услуги заполни:

* **«Команда выдачи на сервере»** — например
  `flx_grant {steamid} {name} {flags}`.
  Подстановки: `{steamid}` — SteamID игрока, `{name}` — ник,
  `{login}` — логин на сайте, `{flags}` — флаги (`b` — generic,
  `c` — kick, `d` — ban, `e` — slay, `g` — чат).
  Для своего VIP-плагина подставь его команду, например
  `vip_add {steamid} 30` — подойдёт любая.
* **«выдавать сразу после оплаты»** — если включено, права улетят на сервер
  в момент оплаты с баланса. Если выключено — админ жмёт «выдать» в заказе.

### Шаг 3b. Если RCON не выполняет команды

Проверено на реальном сервере: RCON-порт и пароль верные, авторизация проходит,
но **команды сервер не выполняет** (в CS:GO это бывает при выключенном
`sv_cheats 1` или когда RCON проксирует панель управления).

На такой случай сделан **агент выдачи** — маленький скрипт на самом сервере,
который получает заявку с портала по HTTP и сам пишет `admins.json` и базу VIP.

Клади `agent.js` на сервер (рядом с `addons/`) и запусти:

```
node agent.js --port 8791 --token СЕКРЕТНЫЙ_ТОКЕН \
     --admins addons/sourcemod/data/admins.json \
     --vipdb  addons/vipmodule/vipusers.db \
     --viptable vipusers
```

Потом в портале: «Управление сервером» -> «Агент выдачи на сервере»:
адрес `http://IP:8791` и тот же токен, кнопка «Проверить связь».

Портал шлёт заявку агенту, и тот пишет права. Никакого RCON не нужно —
работает с любой панелью и любым хостингом.

Порядок выдачи в портале: **агент -> RCON -> база VIP -> admins.json** —
что настроено, то и сработает.

### Шаг 4b. Если у тебя своя база VIP

Если VIP выдаёт плагин, который пишет игроков в SQLite-файл (обычно это
`addons/<плагин>/vipusers.db` или `vip_users.db`), то портал умеет писать
в неё напрямую — без моста и без RCON.

Админка -> «Управление сервером» -> «База VIP»:

* **Файл базы** — путь к .db на сервере (портал должен его видеть);
* **Таблица** — обычно `vipusers`;
* **Формат SteamID** — `STEAM_0:1:XXXXX` или `STEAM_0:X:XXXXX`, как хранит твой плагин;
* **SQL-шаблон выдачи** — например:

```sql
INSERT OR REPLACE INTO vipusers (authid, vip, expiration, credit, ncredit, group)
VALUES ('{steamid}', 1, {days}, {credit}, 0, '{group}')
```

Подстановки: `{steamid}` (в выбранном формате), `{name}`, `{days}`,
`{credit}`, `{group}`. Кнопка «Показать VIP-игроков» выводит текущее
содержимое таблицы — видно, что запись легла правильно.

Если у твоего плагина другая схема — подставь свою, шаблон выполняется
как есть. Для MySQL-варианта потребуется драйвер — скажи, добавлю.

### Шаг 5. Игрок привязывает SteamID

В личном кабинете блок «Игровой аккаунт»: SteamID и ник. Без SteamID
выдача невозможна — портал честно скажет об этом.

### Что где хранится

| что | где |
|---|---|
| аккаунты, баланс, привязки | `data/portal.db` (SQLite) |
| услуги и команды выдачи | там же, таблица `services` |
| настройки сервера и RCON | там же, таблица `settings` |
| права на сервере | `addons/sourcemod/data/admins.json` на сервере |
| лог действий админа | `audit` в базе + раздел «Лог действий» |
