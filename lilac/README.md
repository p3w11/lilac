# 💜 Lilac

Небольшой чат для своих: регистрация, вход, общий чат и личные переписки.
Работает на чистом Node.js, без базы данных — данные лежат в одном файле `data/db.json`.

## Что умеет

- Регистрация по логину и паролю (пароли хранятся в виде хэшей bcrypt)
- Вход / выход, сессия в httpOnly-куке на 30 дней
- **Общий чат** — где все
- **Личные переписки** 1-на-1 (кнопка «+ Написать друга», поиск по логину)
- Доставка в реальном времени через WebSocket, «печатает...», список тех, кто онлайн
- **Отметки о прочтении** — «прочитано» у твоих сообщений
- Счётчики непрочитанных, разделители дат, автопрокрутка
- Адаптив под телефон
- **Группы и каналы**: создание, участники, помощники, публичные каналы
- **Голосовые звонки** один на один в личных переписках: микрофон, mute, сброс
- **Профиль**: своё отображаемое имя, описание «о себе», смена пароля
- **Настройки приватности** — 5 переключателей, как в Telegram/Discord
- **Роли**: участник / модератор / админ, выдаются из админки
- **Админка**: статистика, роли, удаление пользователей и сообщений, очистка чата
- Необязательный **код приглашения**, чтобы посторонние не регистрировались

## Профиль

Кнопка **«Профиль»** внизу боковой панели. Меняются:
- отображаемое имя (до 32 символов)
- описание «о себе» (до 200 символов)
- пароль (нужен текущий)

Логин (`username`) менять нельзя — он служит для входа и не меняется.

Чужой профиль открывается кнопкой **«Профиль»** в списке собеседников. Там видно роль
человека и его описание.

## Настройки приватности

Кнопка **«Настройки»**. Пять переключателей, для каждого три варианта:

| Настройка                   | Что регулирует                                     |
| --------------------------- | -------------------------------------------------- |
| Видимость профиля          | Кто может найти и открыть твой профиль             |
| Видимость онлайна          | Кто видит, что ты сейчас в сети                     |
| Личные сообщения           | Кто может начать с тобой переписку                  |
| Индикатор набора           | Кто видит, что ты печатаешь сообщение               |
| Отметки о прочтении         | Кому отправлять «прочитано»                        |

Уровни: **Все** (по умолчанию), **Только контакты**, **Никто**.

> «Только контакты» = те, с кем уже есть личная переписка. Отдельного списка
> контактов пока нет — если нужны именно заявки на добавление, скажи, добавлю.

Все настройки проверяются **на сервере**: скрытый профиль возвращает 403, запрещённые
личные сообщения не отправляются, скрытый онлайн не попадает в чужие списки. Скрыть
что-то в интерфейсе, не спрятав от сервера, невозможно.

## Роли

| Роль        | Права                                        |
| ----------- | -------------------------------------------- |
| Участник    | Только свой чат                               |
| Модератор   | + удалять любые сообщения                     |
| Админ       | + удалять людей, выдавать роли, чистить чаты |

Роль выдаётся выпадающим списком в админке. Роль владельца (`ADMIN_USER`) менять
нельзя, и его нельзя удалить — иначе можно потерять доступ к админке.

## Админка

Аккаунт владельца создаётся сам при первом запуске.

| Переменная   | По умолчанию | Что делает                |
| ------------ | ------------ | ------------------------- |
| `ADMIN_USER` | `p3w1`       | Логин владельца (всегда админ) |
| `ADMIN_PASS` | `228_1337`   | Пароль при первом запуске |

Войди под этим логином → открой **`/admin`**.

⚠️ **Задай `ADMIN_PASS` в настройках хостинга.** Если пароль остался в коде по умолчанию,
его увидит любой, кто откроет репозиторий на GitHub.

Защита от перехвата: аккаунт владельца создаётся сервером при старте, а не через
обычную регистрацию. Поэтому никто не сможет занять этот логин раньше тебя.

## Быстрый старт у себя

Нужен [Node.js](https://nodejs.org) версии 18 или новее.

```bash
npm install
npm start
```

Открой <http://localhost:3000>, зарегистрируйся — и пиши.

На Windows можно просто запустить **`start.bat`**.

## Настройки (переменные окружения)

| Переменная            | Что делает                                                        |
| --------------------- | ----------------------------------------------------------------- |
| `PORT`                | Порт сервера. На хостинге задаётся сам, локально — 3000            |
| `JWT_SECRET`          | Секрет для подписи сессий. На хостинге **обязательно задай сам**   |
| `INVITE_CODE`         | Если задан — регистрация только с этим кодом                      |
| `ADMIN_USER`          | Логин владельца (по умолчанию `p3w1`), у него всегда роль админа  |
| `ADMIN_PASS`          | Пароль владельца при первом запуске (по умолчанию `228_1337`)       |
| `DATA_DIR`            | Папка с файлом данных (по умолчанию `./data`)                      |
| `DISABLE_RATE_LIMIT`  | `1` — отключить ограничения на вход и регистрацию                  |

Ограничения по умолчанию: **10 попыток входа за 10 минут** и **10 регистраций за час**
с одного адреса. Если все сидят за одним интернетом (например, мобильный оператор
раздаёт один IP), попроси друзей зарегистрироваться по очереди или включи
`INVITE_CODE`. Для локальных прогонов тестов ставь `DISABLE_RATE_LIMIT=1`.

Пример для PowerShell:

```powershell
$env:JWT_SECRET = "длинная-случайная-строка"
$env:INVITE_CODE = "код-для-друзей"
npm start
```

## Как залить на хостинг

Проект подходит под любой хостинг, где есть Node.js и WebSocket.

### Render (самый простой, есть бесплатный тариф)

1. Залей код на GitHub.
2. [dashboard.render.com](https://dashboard.render.com) → **New +** → **Web Service** → подключи репозиторий.
3. Поля:
   - Environment: `Node`
   - Build command: `npm install`
   - Start command: `npm start`
4. В **Environment** добавь `JWT_SECRET` (любая длинная случайная строка).
5. Deploy → получишь адрес вида `lilac-xxxx.onrender.com`.

Или одной кнопкой: в проекте лежит `render.yaml` — на Render работает **New → Blueprint**.

> ⚠️ На бесплатном тарифе Render сервис засыпает, если на него никто не заходил (~5 минут),
> а файлы на диске **не сохраняются** — сообщения пропадут после перезапуска.
> Для переписки с друзьями это обычно не критично, но история может обнулиться.
> Как сделать постоянное хранилище — в разделе ниже.

### Другие бесплатные варианты

| Хостинг                  | Что сделать                                                        |
| ------------------------ | ------------------------------------------------------------------ |
| **Railway**              | New Project → Deploy from GitHub. Тариф trial, потом $5/мес при уведомлении. Легко подключить Postgres, если понадобится |
| **Koyeb**                | New Service → GitHub, region Frankfurt, instance Free. Есть WebSocket |

| **Amvera** / **Selectel** | Есть бесплатные/пробные VPS с Node — подойдёт, если нужен полный контроль |

Пример для Railway/Koyeb — те же команды:

```
Build:  npm install
Start:  npm start
```

## Если нужна постоянная история сообщений

Файловое хранилище не переживает пересоздание контейнера. Два пути:

1. **Бесплатная Postgres БД** — [Neon](https://neon.tech) или [Supabase](https://supabase.com)
   дают бесплатную базу. Скажи — переделаю `lib/db.js` под `pg`, и данные будут вечными.
2. **Дисковое хранилище** — платное, например 1 ГБ от Render.

## Голосовые звонки

Кнопка **«Звонок»** появляется только в **личной переписке** — в группах и каналах
звонков нет.

Как работает: голос идёт **напрямую между браузерами** (WebRTC), сервер только
пересылает сигналы — сам разговор через него не проходит.

В панели звонка:
- **Микрофон** — заглушить себя (можно включить обратно)
- **Завершить** — положить трубку, собеседник сразу увидит
- **Повторить** — если не соединилось, перезвонить ещё раз

Если не отвечают 45 секунд — звонок сбрасывается сам. Если закрыть вкладку во время
разговора — второй человек тоже получит сброс. Если ты уже в звонке, а звонят ещё —
входящий сразу отклоняется.

При принятии звонка браузер спросит разрешение на микрофон. **Без HTTPS микрофон не
работает** — на Render как раз HTTPS.

### Если звонок не соединяется

Причина почти всегда в сети, а не в коде. Статус прямо в панели звонка:
«проверяем путь связи...», «соединяемся...», «соединено» — или «Сеть не дала
соединить напрямую».

Серверов для обхода NAT (STUN) в коде **семь, разных** — если один недоступен,
работают остальные. Но у части мобильных операторов и корпоративных сетей все
STUN-серверы могут быть заблокированы, и тогда нужен **TURN** (он проксирует звонок
через себя).

Свой TURN добавляется в `public/js/chat.js`, в начало блока звонков:

```js
window.LILAC_TURN = [
  {
    urls: 'turn:my-turn-server.com:3478?transport=udp',
    username: 'логин',
    credential: 'пароль',
  },
  {
    urls: 'turn:my-turn-server.com:443?transport=tcp',
    username: 'логин',
    credential: 'пароль',
  },
];
```

⚠️ **TURN нельзя указывать с пустыми логином и паролем.** Chrome падает с
`InvalidAccessError` при создании соединения, и звонки перестают работать вообще.

Бесплатные TURN-серверы: Open Relay (openrelay.metered.ca), Cloudflare, Xirsys,
Metered.ca — после регистрации дают логин и пароль.

### Диагностика

В консоли браузера (F12 → Console) при звонке видно состояние соединения:
`[звонок] ice: checking` → `connected` или `failed`. Если `failed` — сеть не даёт
прямое соединение, нужен TURN.

## Группы и каналы

Кнопки **«+ Группа»** и **«+ Канал»** в боковой панели.

**Группа** — пишут все участники. **Канал** — пишут только владелец и помощники,
остальные читают (как в Telegram). Публичный канал читают все, кто зашёл на сайт.

Кнопка **ℹ** у группы или канала открывает настройки:
- переименовать, изменить описание (владелец и помощники)
- добавить участника по логину (владелец и помощники)
- назначить и снять помощника (только владелец)
- убрать участника (владелец и помощники)
- покинуть группу (владелец не может — сначала передай права или удали)

Защита от потери доступа: владельца нельзя убрать из группы, покинуть её или
понизить роль. Права проверяются на сервере — участник не может ни переименовать
группу, ни убрать кого-то, даже если подделает запрос.

В админке есть раздел «Группы и каналы» — можно удалить любую комнату.

## Тесты

```bash
npm start                  # в одном окне
DISABLE_RATE_LIMIT=1 npm start   # или так, если упираешься в лимиты
npm test                   # в другом
```

Пять наборов: `test/e2e.js` — регистрация, вход, чат; `test/admin.js` — права и
модерация; `test/features.js` — профиль, приватность, роли, прочтения;
`test/rooms.js` — группы и каналы; `test/calls.js` — сигналинг звонков.
Всего 100 проверок. Звук самих звонков тесты не проверяют — нужен браузер с микрофоном.

## Безопасность

- Пароли только в виде bcrypt-хэшей, в коде их нет
- Cookie `httpOnly` + `SameSite=Lax`, на HTTPS ещё и `Secure`
- Ограничение попыток входа: 10 за 10 минут с одного IP
- Все сообщения вставляются через `textContent` — HTML и скрипты не выполняются
- Доступ к личной переписке проверяется на сервере по ID пользователя
